## One-variable rationale and MZ600 provenance

- The **original Motorola bootloader protocol** names the six-byte factory WLAN address `ATAG_STINGRAY_MAC=0x57464d41`. The product name Wingray does not imply a new vendor ATAG type; code accepts original tag and limits its use to `motorola,xoom` FDT root plus known `/mmc@c8000200/wifi@1` device node.
- Earlier MZ600 actual Debian physical success demonstrated live `/proc/device-tree/mmc@c8000200/wifi@1/local-mac-address` **equal** to `wlan0` interface address, but without independent factory assignment proof. [Earlier physical checkpoint](https://github.com/Olsens11/XoomLinux7/blob/wip/clean-wifi-bt-usb-20261025/docs/checkpoints/NATIVE_DEBIAN_SD_BOOT_USB_WIFI_IDENTITY_PHYSICAL_PASS_2026-10-25.md) and [original lab BOOT-01 patch](https://github.com/Olsens11/XoomLinux7/blob/wip/clean-wifi-bt-usb-20261025/patches/upstream/review-arm-atag-20261028/0001-ARM-tegra-propagate-Stingray-WLAN-MAC-ATAG-to-FDT.patch).
- **Current MZ604 live prepatch:** `CONFIG_ATAGS=y`, `CONFIG_ATAGS_PROC=y`, `CONFIG_ARM_ATAG_DTB_COMPAT=y`, `CONFIG_ARM_APPENDED_DTB=y` in existing build; yet live `/proc/atags` absent and `local-mac-address` absent. Generic BCM4329 firmware `4.220.48` physically brings up `wlan0` but address is known Broadcom sample `00:90:4c:12:34:56`. The source patch rejects zero, multicast and both known Broadcom samples, and has NO fabricated MAC fallback. Actual MZ604 vendor tag presence is **unmeasured before next cold boot**.
- Earlier MZ600 modern `chanspecs` compatibility issue with OEM `4.218.248.x` became unnecessary for first Wingray interface creation using exact generic `4.220.48`; no WIFI-01 fallback applied. Generic fw advertises **only 2.4 GHz** on this MZ604: channels 1–11 available, 12/13 `no IR`, 14 disabled. No scan, connection, RF transmission or country override in this trial.
