## What is actually proved and what remains unproven

- A **single scan generated within a V24 live module** has firmware-echoed `0x1235` (4661), successful terminal-only owner routing, and proper cfg80211 completion. Two instances of the first scan corroborate that. This is enough to demonstrate correct basic generation initialization and per-terminal ID agreement; **not** enough to demonstrate **increments** because the second request never reached the driver scan setup.
- `Operation not permitted (-1)` on second request is now directly captured. V20/V24's constrained `brcmf_cfg80211_scan` gate returns `-EPERM` if request differs from precisely one no-IR ch36 passive channel, zero SSIDs and zero IE bytes. It also propagates the firmware `BRCMF_C_SET_PASSIVE_SCAN` error if any. The absence of the gate-pass marker on second scan makes the **strict test guard a leading explanation**, but the rejected field has NOT yet been measured and denial could occur earlier in nl80211/cfg80211. Do NOT weaken NO_IR, passive RF restriction merely to get another run. Next narrowed diagnostic: log numeric `request->n_channels`, `n_ssids`, `ie_len`, frequency and flags **at gate reject** with validated, bounds-safe access; capture original `iw` errno and whether cfg80211 callback even entered. Then modify only justified host/test semantics if required.
- Important misleading inherited V23 message: V24 log `MZ600_V24_SCAN_REQUEST_SYNC id=4660` still prints the **old lab module parameter**, although generation mode overrides firmware request to 4661. The actual `NEW_SCAN_GENERATION id=4661` and firmware **echo 4661** corroborate true value. Correct future source diagnostic to log *effective wire ID*; do not use that stale marker as the request measurement.
- The V24 lab candidate is **not an upstream-quality race-safe patch**. Need per-scan increment in one loaded module; old completion after abort/timeout/second scan, generation wrapping, locking and teardown lifetime, multi-interface/P2P constraints, other firmware/chip regressions, 2.4GHz and other Xoom variants.
- For test harness, package both exact-ABI modules and account for automatic WCC request: use a hash-guarded temporary matched-WCC module bind only if the original WCC path is independently verified, and verify hash-restoration after unmount. **No permanent module overwrite; no weakening kernel symbol checks.**
