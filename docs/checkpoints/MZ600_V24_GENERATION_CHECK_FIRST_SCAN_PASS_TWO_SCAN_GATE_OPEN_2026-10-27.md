## Root-cause distinctions and next narrow gates

1. **Known matched-module requirement:** V24 changes `struct brcmf_cfg80211_info` (via `escan_info`) and thereby exported module symbol CRCs. Standard Linux modules must be built and loaded as an ABI-matched set. Manual loading matched WCC *after* brcmfmac is subject to automatic plugin request racing ahead and selecting installed mismatched WCC. V24D's **temporary, hash-verified WCC bind overlay** over the standard installed module path, applied after quiescing radio and removed during cleanup, physically proved kernel's own automatic loading can use the matched module without replacing disk files. Preserve as a **test harness mechanism**, not as production kernel logic.
2. **Known completed V24 functional mechanism:** first generated request ID 4661 was returned by original firmware as terminal `sync_id=4661` and accepted by existing cfg80211 path via the V21 owner routing when the decoded terminal bsscfg index was **16**. This is independent physical proof of generation validation for one scan inside a loaded module. It does NOT prove increment to 4662 or late-event rejection.
3. **Unresolved second scan `-EPERM`:** V24D second passive `iw` request was rejected in 26ms with `Operation not permitted (-1)`, and no second `MZ600_V24_NEW_SCAN_GENERATION` marker appeared. Upstream source `net/wireless/nl80211.c::nl80211_trigger_scan` routes the request through `cfg80211_scan`. The temporary V20/V24 `brcmf_cfg80211_scan` strict lab gate can explicitly return `-EPERM` **before its `MZ600_V24_SCAN_GATE_PASS` log** if channel/request predicates (including expected `IEEE80211_CHAN_NO_IR`) are not met. **This is a plausible explanation, not yet established**. Do not silently relax NO_IR/passive or regulatory behavior. Next evidence should capture read-only channel flags/request properties for both scans and precisely log the rejected predicate; preserve firmware and driver unchanged until reason proven.
4. **Patch correctness still OPEN:** generation state shared across cfg80211 scan, timer/abort and fweh worker requires lifetime/locking review, stale/canceled/duplicate terminal tests, wrap, P2P/multi-interface validation, regulatory / 2.4GHz / other firmware and other Xoom regressions. Fix misleading V24 request-ID diagnostic in new source revision. The V24 builder currently source-restores the modified `cfg80211.h`, `cfg80211.c`, `fweh.c` and original core .ko, but Kbuild also generates updated WCC object artifacts/Module.symvers in the separate kernel build tree; keep an explicit immutable matched-WCC artifact and an ABI coherent build recipe for future patch-series integration. Never treat a compiler pass as full multi-module compatibility proof.

**Verdict:** V24 generation match and owner handoff physically proven for one scan; *two successive scans in a single module lifetime* and production race safety **OPEN**, with a newly isolated userspace `-EPERM` request failure. No on-chip firmware changes or persistent installation changes.
