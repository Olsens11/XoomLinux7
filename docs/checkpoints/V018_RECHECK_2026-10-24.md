The prior v018 checkpoint recorded a host clock of **46,153,846 Hz** using the same artifact hash, whereas this actual running v018 instance reports **25,000,000 Hz**. The compiled v018 USB diagnostic DTB `max-frequency` property was independently read back as `46153846`, i.e., a ceiling rather than necessarily its current clock. The discrepancy might depend on dynamic MMC/card/driver state; it is **not yet explained**, and it would be incorrect to assume a fixed clock per image without measuring at each attempt.

The source checkout also contains a **separate v019 25-MHz-capped experiment** and its own checkpoint; do not relabel this v018 live observation as v019, and do not overwrite either original record. The F2 failure remained the same in this run.

## Existing on-demand kernel infrastructure: read-only feasibility
The on-device `SDIO` diagnostic command enumerated `/sys/bus/platform/drivers/sdhci-tegra` with `bind`, `unbind` and the target `c8000200.mmc`. The `uevent` file identifies it as `mmc2`; the other instances `c8000400.mmc` and `c8000600.mmc` must not be touched. This suggests guarded MMC2-only rebind is a viable experiment, **not yet implemented or tested**. See [on-demand design](../architecture/MMC2_ON_DEMAND_DESIGN.md).
