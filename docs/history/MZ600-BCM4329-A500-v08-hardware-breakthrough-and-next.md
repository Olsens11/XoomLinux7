## EXACT UPSTREAM CROSS-DEVICE REFERENCE
- **Acer Iconia Tab A500 (Picasso)** has SAME Nvidia Tegra 2 and **actual BCM4329 module** (explicit comment: `Azurewave AW-NH611 BCM4329`, unlike other boards which only use BCM4329 as compatibility fallback for later chips). In current upstream Linux DTS `arch/arm/boot/dts/nvidia/tegra20-acer-a500-picasso.dts`, SDMMC1 powers from 3.3V and 1.8V, `mmc-pwrseq-simple`, 32kHz RTC ext clock, reset GPIO K6 active low, post-power-on-delay 300ms, 4-bit SDIO, non-removable, host-wake GPIO S0, `compatible = "brcm,bcm4329-fmac"`. Xoom has SDMMC2, vmmc GPIO U4 and 1.8V vwlan1, reset GPIO U2, hostwake U5; these differences are device-specific and MUST NOT be transplanted as-is. **Use Acer for control-flow and standards, not GPIO pins.**
- Original upstream source/code: https://kunit.googlesource.com/linux/+/refs/heads/torvalds/master/arch/arm/boot/dts/tegra20-acer-a500-picasso.dts or kernel `linux-src/arch/arm/boot/dts/nvidia/tegra20-acer-a500-picasso.dts`; Linux patch https://lkml.indiana.edu/hypermail/linux/kernel/2004.2/01810.html.
- Further references: Linux Wireless brcmfmac documentation https://wireless.docs.kernel.org/en/latest/en/users/drivers/brcm80211.html ; upstream SDIO firmware/NVRAM semantics and Broadcom kernel DT binding `brcm,bcm4329-fmac`.
- Reverse engineering published: Andrés Blanco and Matias Eissler, *One firmware to monitor 'em all*, 2012 BCM4325/BCM4329 paper, https://www.coresecurity.com/core-labs/publications/one-firmware-monitor-em-all . ### NEW key discovery: Motorola bootloader passes per-device MAC, potentially calibration data
- Android Google original Motorola Stingray source `board-stingray-wifi.c`, publicly available https://android.googlesource.com/kernel/tegra/+/eb4e253d7d76f6093ef50597e909157c21803842%5E2..eb4e253d7d76f6093ef50597e909157c21803842/ , defines `ATAG_STINGRAY_MAC 0x57464d41` and `parse_tag_wlan_mac` to copy **bootloader-provided per-device MAC** into `stingray_mac_addr`, exposed via `stingray_wifi_get_mac_addr` callback. This matches replacement Android `dmesg` line `WiFi MAC Addr [4] = 0x57464d41`. This is **the portable hardware MAC provenance mechanism**, not file-static macaddr from another Xoom.
- Same Motorola source includes `board-stingray-wlan_nvs.c`, vendor tag `ATAG_WLAN_NVS 0x57494649`, described as extracting Wi-Fi calibration information from the bootloader. Need inspect exact runtime paths and whether replacement Android exposes `/proc/wlan_nvs` and whether the bootloader passes calibration there. Do not falsely assume tag always available on all Xoom variants. Two ancient MAC fallback addresses (e.g. 00:90:4c default) are known, should reject placeholders; source randomizes tail for missing factory data, never interpret as true factory identity. Device-specific actual Android WLAN0 global/unicast MAC saved privately on Surface, not in shared image.
- Strong proposed upstream-aligned solution: preserve bootloader MAC and board NVRAM via a minimal, **generic ARM DT/ATAG handoff** or a board-specific Xoom firmware/calibration provider that extracts vendor tags from this device at boot; do not embed MAC, secrets, regulator-country overrides into shared kernel. The original Linux 7.0 ARM DT conversion's ability to retain custom ATAGs must be examined; if not, deliberate minimal parser/early handoff, review upstream binding conventions. Use OEM source **as hardware documentation**, upstream MMC/regulator/brcmfmac framework, no resurrection of Android Bionic/legacy bcmdhd as permanent driver.
- Also review full OEM country translation table in `board-stingray-wifi.c`; standard Linux cfg80211 regulatory integration preferred; must avoid canned universal US/XY variants.
