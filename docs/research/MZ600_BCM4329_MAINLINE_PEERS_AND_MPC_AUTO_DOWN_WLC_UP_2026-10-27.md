# BCM4329 on other modern Linux devices: MPC auto-down and UP recovery reference

**Research date:** 2026-10-27. **Status:** external source review plus read-only comparison against the pinned xoom-linux/Linux7 tree. No newly executed hardware test, firmware change, or patch. Consult [the V30 physical checkpoint](../checkpoints/MZ600_V30_FIRMWARE_UP_LOST_BETWEEN_ESCANS_PHYSICAL_PASS_2026-10-27.md) for exact Xoom evidence.

## Precisely what needs explaining

V30 physically observed firmware **WLC_GET_UP=1** throughout the first normal multi-channel scan (19 BSS / 3263ms) and immediately following the existing successful **mpc=1** restoration. About 4.09 seconds later, before the second scan, firmware reported **WLC_GET_UP=0** with Linux **host_ready=1, netdev_running=1**, and firmware **mpc=1**. Setting MPC back to 0 succeeded but did not immediately bring UP back to 1; second ESCAN sync4662 failed Linux -52. A separately instrumented V27 trial established the vendor status **BCME_NOTUP=-4** in an analogous failed second ESCAN. The transition and mismatch are verified; its exact trigger is not.

## Exact same-era maintained-linux peers

**Acer Iconia Tab A500** — Tegra20, 2011–12 **BCM4329 SDIO Wi-Fi + UART Bluetooth**. Kernel developer Dmitry Osipenko [reported successful mainline/linux-next Wi-Fi, about 40 Mbit/s](https://lkml.iu.edu/hypermail/linux/kernel/2008.3/08366.html) after upstream driver/SDIO work in 2020. [Specific F2 watermark patch](https://lkml.iu.edu/hypermail/linux/kernel/2008.3/08365.html) addresses a Tegra20 BCM4329 RX CRC error. Other changes select 128-byte F2 blocks and correct SDIO pinmux. These are real, useful reference patches but **they do not themselves address controller idle-DOWN or second ESCAN**.

The [A500 mainline DTS](https://kunit.googlesource.com/linux/+/refs/heads/torvalds/master/arch/arm/boot/dts/tegra20-acer-a500-picasso.dts) defines **mmc-pwrseq-simple, fixed reference clock, host-wake, reset timing, regulators, keep-power-in-suspend**. Pin numbers and delays are A500-specific and must not be transplanted to Stingray.

**ASUS Transformer TF101** — Tegra20 and **Azurewave AW-NH615 BCM4329B1**, with [Linux device-tree support](https://lkml.rescloud.iu.edu/hypermail/linux/kernel/2112.1/04483.html), SDIO, host-wake, and Wi-Fi power sequencing. The [TF101 Linux image project](https://github.com/antonialoytorrens/TF101-linux-images) has operational Wi-Fi documentation, but some historical versions use **downstream BCMDHD**, so distinguish firmware/driver variants instead of treating all TF101 outcomes as brcmfmac proof.

**Our pinned upstream source already incorporates key A500-era work:** in xoom-linux/linux at commit 2404d27378503b4df74ab2cb0a8b7cd6cf9d5fc3, brcmfmac/bcmsdh.c defines and selects **SDIO_4329_FUNC2_BLOCKSIZE=128**, brcmfmac/sdio.c shares the **CY_4339_F2_WATERMARK=48** path with BCM4329, and brcmfmac/feature.c enables **NEED_MPC** for BCM4329. Stingray lab DTS already describes wifi-pwrseq / mmc-pwrseq / keep-power-in-suspend / host-wake (not yet a validated exact-board equivalence). **Do not rewrite these upstream changes as new Xoom patches.**

## Most directly relevant EXISTING Broadcom code

Android's vendor [BCMDHD wl_cfg80211.c](https://android.googlesource.com/kernel/msm/+/68cdc8df1cb6622980b791ce03e99c255c9888af/drivers/net/wireless/bcmdhd/wl_cfg80211.c), function **wl_cfg80211_set_auto_channel_scan_state**, explicitly documents **"Disable mpc, to avoid automatic interface down"**. It performs the ordinary Broadcom **mpc=0** firmware iovar write and then **WLC_UP** to set the interface **up explicitly**, before its channel selection path. [Android common bcmdhd 3.10](https://android.googlesource.com/kernel/common/+/bcmdhd-3.10/drivers/net/wireless/bcmdhd/wl_cfg80211.c) has a similar sequence and restores mpc=1 when channel selection ends. [Fuchsia-hosted older BCMDHD reference](https://fuchsia.googlesource.com/third_party/bcmdhd/+/e7ce8d184174f6bcdc02e4b6c8010b8e098e6b10/wl_cfg80211_v1.c) also explicitly pairs these operations. [BCM4329-era Broadcom ioctl definitions](https://android.googlesource.com/platform/hardware/broadcom/wlan/+/492884be0b302c6c6ea51b360c1f7b0996d96a8b/bcm4329/src/include/wlioctl.h) define WLC_UP=2, WLC_DOWN=3 and WLC_GET_UP=162.

**Interpretation:** Broadcom software has a **recognized concept of MPC-associated automatic interface down** and a **documented UP transition** to make the controller available for an operation. This is the closest directly applicable code example to V30's observed state mismatch. But the cited sequence is inside special **automatic channel selection**, not ordinary Linux station ESCAN. It is **not** authority to add unconditional WLC_UP to every scan, keep MPC permanently off, bypass cfg80211, or reset shared Wi-Fi/Bluetooth resources. Xoom's regular brcmfmac scan already writes mpc=0 before ESCAN and mpc=1 after completion; that part is implemented and tested.

## Another significant source: firmware/API compatibility is not interchangeable

The official [linux-firmware 5aa0b27d commit (February 10, 2023)](https://kernel.googlesource.com/pub/scm/linux/kernel/git/hansg/linux-firmware/+/5aa0b27d923ac1d2ee4f1d7becfd21c5968769a1) **reverted a BCM4329 firmware replacement** because it broke NVIDIA Tegra devices: a required brcmfmac firmware API command was unsupported in the replacement binary. Arend van Spriel authored it; Dmitry Osipenko reported it. This is direct maintainer evidence of **versioned firmware/driver interoperability requirements**, but the commit does **not** identify the command or establish the cause of Xoom's idle DOWN.

Our installed/original BCM4329 firmware and temporarily overlaid Motorola 2012 firmware have **different versions**, and older firmware may lack ESCAN and other ioctls. Keep original NVRAM/calibration and firmware private; do not copy Acer NVRAM or regulatory settings, and never permanently replace firmware merely for testing. A later exact-hash **RAM-only firmware A/B**, if both binaries support comparable operations, could distinguish a firmware-specific policy from generic brcmfmac.

## Evidence-grounded next tests — no change was made during this research

**A. Highest-value narrowly controlled experiment:** With normal regulatory-safe scan, existing mpc=0 on entry, query **WLC_GET_UP** at the start of each scan. **Only if the controller is 0**, run the old Broadcom **WLC_UP** command once as a LAB-only, chip-scoped transition, log both return codes, read WLC_GET_UP again, and submit the unmodified next ESCAN with a distinct generation ID. Compare to unaltered V30 after a similar idle gap. Two genuine Event69 completions (not host-submitted IDs alone) plus independent rollback would be strong evidence for normal controller wake/resynchronization. Parameter semantics and safety must be checked first; NO generic unconditional reset or permanent patch from one positive test.

**B. Cause isolation:** Observe WLC_GET_UP at points within the **4-second idle window** and correlate MPC=1, SDIO runtime PM and available firmware events. If needed perform **one-variable** strictly RAM-only MPC idle-state A/B; even if MPC-off prevents DOWN, **permanent disabling power management is not an acceptable production conclusion** without power/BT/PM analysis.

**C. Compatibility check:** Compare a separately validated kernel-compatible BCM4329 firmware version with the OEM 2012 candidate under the same exact module if and only if both support identical ESCAN semantics. A missing ESCAN ioctl in older firmware is not evidence of a state-machine fix.

**State after research:** The Acer A500 confirms that **modern brcmfmac can operate BCM4329 on Tegra20**, the vendor BCMDHD driver supplies a source-grounded **conditional bring-UP design precedent**, and the 2023 firmware revert warns about API compatibility. None yet proves a production fix for Motorola OEM 2012 firmware. Do not alter the canonical upstream patch series until a safe, reproducible causal test. Follow [G01–G12 standards](../../patches/upstream/candidate/SUBMISSION_REQUIREMENTS.md) and normal Desktop→Surface→COM9 rollback.
