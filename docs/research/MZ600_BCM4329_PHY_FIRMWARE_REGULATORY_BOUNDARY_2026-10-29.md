## Minimal intent-preserving design choice

1. **Do not generate synthetic `per_chan_info` replies, substitute datasheet RF characteristics for legal restrictions, set arbitrary US/69 or `alpha2=99` globally, or bypass `cfg80211` regulation.** The PHY's power/calibration/receiver hardware already operates under embedded firmware control.
2. Preserve the modern `chanspecs` branch, legacy `GET_VALID_CHANNELS` fallback and Broadcom's already established capability/policy refresh points. Treat firmware-current channel list separately from immutable hardware capability and from Linux/regdb country policy. Distinguish native BCME status from normalized `-EBADE`.
3. **Resolve firmware country provenance first.** The source-only, one-file [lab readback patch](../../tools/diagnostics/mz600-country-iovar-readonly-lab-only-20261029.patch) executes only `brcmf_fil_iovar_data_get(ifp,\"country\",...)` during attach for BCM4329 and reports country abbreviation, internal country code and firmware revision. It has **no firmware SET IOCTL**, no RF scan/power changes. Built offline on desktop using original exact-nine pinned source; `brcmfmac.ko` size **342864**, SHA **`e542bdbd5bb25167a15138d977df2e68d93db9fb509c0f23526bfad19b368424`**, vermagic `7.0.0-next-20260422+ SMP mod_unload modversions ARMv7 p2v8`, imported CRCs **259/259 equal** original validated module; WCC imported CRCs **7/7 equal**. **MODULE NEVER LOADED ON DEVICE**. No permanent changes. This is not a WIFI-01 candidate and must not be merged into upstream patch.
4. Only after country readback: decide whether the smallest *board-specific* preexisting mechanism `brcm,ccode-map` is actually needed and applicable to MZ600 US variant, and whether a valid signed database is accepted. Then modify *existing* WIFI-01 for the smallest missing compatibility behavior, preserving country changes rather than freezing current firmware channel list into `orig_flags` forever. Separate board-DT scope from brcmfmac channel logic when they are independent logical problems.
5. Source and offline tests first, then a specifically gated temporary experiment with original firmware/module SHA and Wi-Fi reconnection checks, preserving Debian p10 and complete rollback. Do not claim 5 GHz regulatory/normal-operation acceptance without actual hardware results.
