## 4. BCM4329 technical chronology — physical evidence versus hypotheses

### 4.1 SDIO, firmware, board and initial bring-up

Initial Linux7 v0xx/early v06x work struggled with SDIO function2 `-ETIME/-62`, PM and reset/power sequencing, voltage/core power-on waits, LPO, `WL_REG_ON` and `BT_REG_ON`. Source study included BCM4329 datasheet (e.g. >110ms VDDC stabilization), Motorola Tegra downstream driver and Android SDIO implementation, Broadcom NVRAM, firmware shared memory and CPU boot. A corrected end-of-firmware NVRAM RAM pointer allowed the Cortex-M3 to boot and parse calibration. Host modifications studied runtime-PM locks, hold SDIO clocks across init, host block size/IRQ order, no globally disabling ADMA. Later actual Linux `wlan0`, scan records and cfg80211 appeared. These are validated historical discoveries but do not prove every current power/suspend configuration is safe. Continue [chip integration ledger](../research/MZ600_BCM4329_LINUX7_WHOLE_CHIP_PATCH_INTEGRATION_LEDGER_2026-10-26.md) and original [comprehensive BCM4329 handoff](MZ600_LINUX7_BCM4329_COMPREHENSIVE_HANDOFF_2026-10-25.md).

### 4.2 Actual dual-band A/B and the regulatory memory

The user correctly recalled that early 5GHz success coincided with original Motorola **US region / regulatory revision 69** and the HRI39 firmware. Reconstructed **causal controls**:
- Generic Debian `4.220.48` (September 2011), original 1550B calibration: raw firmware **GET_BANDLIST count1, band2=2.4GHz**, `chanspecs` 11×2.4GHz. That is a firmware response, not just an `iw` UI problem.
- Generic SAME firmware, OEM `ccode=US,regrev=69` NVRAM/bootstrap: 5GHz still **not** advertised. US69 alone was **insufficient**. Some historical country readback tests corroborated US69 but exact stage/protocol should be checked against immutable checkpoints before broad generalization.
- Motorola HRI39/66 firmware `4.218.248.20` + OEM/US69 calibrated context: **2G+5G**, 11×2.4GHz + 9×5GHz; passive ch36 WLC_SCAN/IOCTL51 returned valid 5GHz BSS records, but ESCAN often unsupported. The initial OEM case changed firmware and regulatory together: do not infer sole causality.

Thus **firmware identity alone changed 5GHz enumeration**, while regulatory settings still govern legal channel use. A numerically “larger” 4.220 version is not necessarily newer or better than OEM build dated 2012.
- Surface independent WLAN scan found a real nearby channel153/5765MHz AP; tablet with installed generic firmware is currently associated on **2.4GHz ch11/2462MHz**, even though the SSID contains “5G.” Network names are not RF-band evidence.
