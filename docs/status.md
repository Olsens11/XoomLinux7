## v040 Motorola default MAC bootstrap provenance — 2026-10-24 (research branch)

An authoritative same-generation source audit discovered Motorola `dhd_common.c` explicitly states a default MAC must be present **in OTP or NVRAM to bring up firmware**, while the unique bootloader `ATAG_STINGRAY_MAC` address is applied later via `dhd_custom_get_mac_address` / `cur_etheraddr`. Motorola `Makefile` enables GET_CUSTOM_MAC_ENABLE and CUSTOMER_HW2 and original bcm4329.ko contains the relevant compiled symbols. The current Linux reference NVRAM has the exact 51 shared values but **does not contain `macaddr`**, whereas OEM has `macaddr`, `ccode`, and `regrev`. This is a **credible, unproven** F2 boot prerequisite if device OTP provides no default MAC; a factory OTP MAC could already satisfy it.

A private temporary locally administered test-MAC was prepared but the Surface's existing `Xoom-v34-BluetoothLiveLab.ps1` **intentionally rejected NVRAM identity/regulatory overrides before opening an upload**, so **NO v040 MAC/NVRAM physical test occurred**.
