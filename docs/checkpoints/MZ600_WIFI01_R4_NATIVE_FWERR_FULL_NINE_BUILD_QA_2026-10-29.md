## Root cause and earlier measured discriminator

- In pinned Linux 7 `brcmfmac/fwil.c`, the protocol returns **both a transport error and a native Broadcom firmware error**. The stock FIL layer collapses multiple native errors to Linux `-EBADE=-52`. It also has a shared `ifp->fwil_fwerr` flag to return firmware codes for feature detection, but toggling that global per-interface flag during concurrent firmware I/O is not an ideal ABI for a new error-specific fallback.
- Earlier [Oct29 physical six-format test](MZ600_WIFI01_BCME_SIXFORMAT_NATIVE_UNSUPPORTED_PHYSICAL_PASS_2026-10-29.md) actually measured **transport0, native BCME_UNSUPPORTED=-23, Linux-facing -EBADE=-52** for all six input variants of `per_chan_info` on Motorola firmware 4.218.248.44. Prior repeated scans had **BCME_NOTUP=-4** concealed by the same normalized Linux code. Therefore the original r3 criterion `err==-EBADE` is insufficient evidence that a firmware command is unsupported.
- Fresh [Oct29 dual firmware A/B](MZ600_OEM2012_FIRMWARE_COUNTRY_US_REV0_DUAL_BAND_RAM_TEST_ROLLBACK_PASS_2026-10-29.md): both generic 4.220.48 and original Motorola 2012 4.218.248.44 reported `US/US/regrev0` using unchanged installed NVRAM, while only Motorola exposed 2.4+5GHz. **Do not force US/69** or mistake current-channel inventory for national transmit permission.

## Chosen minimal implementation: one amended WIFI-01 patch

[Source-only exported r4 four-member series](../../patches/upstream/review-wifi-four-logical-20261029-r4/README.md) replaces r3. Exactly one logical problem — **truthful BCM4329 legacy firmware channel-information API adaptation** — is amended **inside the existing WIFI-01 member**, rather than introducing another fixup patch.

- `fwil.c` threads an optional `s32 *fwerr_out` through its existing mutex-protected firmware command helper. It initializes the output to 0 and fills it only on successful transport return. Ordinary callers pass `NULL` and keep existing error normalization; no `ifp->fwil_fwerr` global-state toggle is introduced by this patch. Common-path wrappers share existing iovar/bsscfg marshaling and buffering.
- `fwil.h` exposes two ordinary same-module helpers for per-call native error readback, **not exported cross-module symbols**.
- `cfg80211.c` only on BCM4329 requests `chanspecs` using this native-error out-pointer and enters existing bounded `WLC_GET_VALID_CHANNELS` fallback **if actual native code is `-23`**. Unexpected raw error `-4` or other normalized `-EBADE` cannot masquerade as lack of support. Its optional `per_chan_info` raw-BCME query likewise caches unavailability **only on native `-23`**. Little-endian marshaling matches the old int-query helper.
- **No change** to ordinary modern `chanspecs` path on non-BCM4329, nor to WIFI-02/03/04 code hunks. Normalized patch-content comparison for WIFI-02/03/04 **PASS exact**; expected `From` commit IDs and `index` values differ because earlier WIFI-01 commit was amended.
- This **does not settle** missing `per_chan_info` regulatory metadata: r4 intentionally retains r3's provisional **NO_IR on 5 GHz** where firmware metadata is unknown. That is a *conservative diagnostic gate*, not proven production-safe equivalence. A currently valid channel is not permanent factory support. Dynamic `cfg80211` country transitions, DFS/passive flags, legal 5 GHz and repeat-scan need further evidence before acceptance.
