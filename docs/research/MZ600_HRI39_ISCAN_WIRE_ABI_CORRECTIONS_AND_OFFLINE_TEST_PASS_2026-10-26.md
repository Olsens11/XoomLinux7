## Critical source-level corrections to external Google draft

1. **Legacy chanspec** is **`0x1B24`** for 5180MHz channel36 5GHz 20MHz no sideband:
  `WL_CHANSPEC_BAND_5G=0x1000 | WL_CHANSPEC_BW_20=0x0800 | WL_CHANSPEC_CTL_SB_NONE=0x0300 | 36=0x0024`.
  Google's `0x3024` includes invalid bandwidth/sideband/band mix for this ABI; do NOT send it.
2. **ISCAN header is eight bytes, not 12**, exactly `struct { u32 version; u16 action; u16 scan_duration; wl_scan_params_t params; }`. Offsets: version=0, action=4, scan_duration=6, scan_params=8. No standalone Pad16 and no `u32 scan_duration`.
3. **Full scan parameters** begin with `wlc_ssid_t ssid` (u32 length+32 bytes), then bssid u8[6], bss_type s8, scan_type s8, nprobes s32, active_time s32, passive_time s32, home_time s32, channel_num s32, channel_list u16[1]. Relative scan offset: `ssid=0, bssid=36, bss_type=42, scan_type=43, nprobes=44, active_time=48, passive_time=52, home_time=56, channel_num=60, channel_list=64`.
4. **One-channel request size** under native 32-bit ABI is **76 bytes**, NOT `sizeof(wl_iscan_params_t)+8`. `wl_scan_params` fixed header=64 bytes; with one channel: 2 bytes plus 2 bytes tail pad for 32bit alignment. `8 + 64 + 4 = 76`. Under the tested natural C layout `sizeof(wl_scan_params_t)=68`, `sizeof(wl_iscan_params_t)=76`. Avoid manually `__attribute__((packed))` these historical structures. Static_assert/BUILD_BUG_ON against `offsetof` and `sizeof` in the target ARM build. For CONTINUE/ABORT use source-consistent zero-initialized request params/length; verify exact firmware acceptance before assuming header-only 8 bytes is allowed.
5. **`brcmf_fil_iovar_data_set` already prepends the null-terminated name.** Actual pinned Linux7 `fwil.c` `brcmf_create_iovar` calculates `strlen(name)+1`, `memcpy(name)`, `memcpy(payload)` immediately afterwards: `"iscan\\0"` is 6 bytes, so 76-byte input becomes 82-byte control command payload *before* SDIO/CDC framing. Do not invent an extra 8-byte tracking header, or claim an absolute four-byte alignment rule for the entire iovar string+payload.
6. **Strict passive intent:** original Broadcom scan prep defaults `scan_type=0` and `nprobes=-1` (unsafe to reuse for NO_IR). Set `WLC_SET_PASSIVE_SCAN=1` and `scan_type=WL_SCANFLAGS_PASSIVE(1)`, `nprobes=0`, `active_time=0`, explicit safe bounded passive dwell, `channel_num=1`, `chanspec=0x1B24` with `n_ssids=0`, broadcast SSID length0, original world and firmware channel verification. Preserve and restore original global passive setting when exiting. A global setting is defense-in-depth, **not a proven radio-quiet guarantee** for the untested firmware iscan code.
7. **Set `iscan START` is the scan trigger.** Do not also issue `WLC_SCAN=50`. GET `iscanresults` yields `status u32 + wl_scan_results {buflen u32,version u32,count u32, BSS[]}`; fixed header=16 bytes. `PENDING=2`: re-poll only; `PARTIAL=1`: validate/read batch, send iscan CONTINUE=2, re-poll; `SUCCESS=0`: validate final batch then complete; `ABORTED=3` and `NO_MEM=4`: complete aborted. Unknown/invalid statuses fail closed.
8. **No premature done:** HRI39 ioctl51 valid 3 BSS is NOT a scan-terminal predicate. `iscanresults` status only governs an **iscan STARTed** session. For such a session, check actual status and batch count/length/version/bounds, avoid duplicated BSS, only emit info for allowed channels. Existing experimental BSS108 parsing and channel validation must be preserved.
9. **Actual Linux7 cfg80211 completion contract:** pinned `cfg80211.c` `brcmf_notify_escan_complete()` uses `struct cfg80211_scan_info info = {.aborted=aborted}; cfg80211_scan_done(scan_request,&info)`; the request is `cfg->scan_request`. There is NO known `ifp->vif->scan_request` mutex. Existing `brcmf_abort_scanning()` calls the escan handler with `fw_abort=true` and may send `BRCMF_C_SCAN` to firmware; ifcan/iscan patch must NOT reuse this as an ordinary iscan abort without adjusting operation ownership/firmware abort semantics. The current escan timer/work and device remove/suspend paths must be coordinated to guarantee exactly-once release and no IOCTL on invalid interface.
10. **Do not invent a 6–8s universal watchdog**. Actual HRI39 iscan runtime not measured. Retain conservative bounded lifetime until data proves safe; historical Android iscan timer often ~8s *between polls*, not a measured hard completion deadline.
