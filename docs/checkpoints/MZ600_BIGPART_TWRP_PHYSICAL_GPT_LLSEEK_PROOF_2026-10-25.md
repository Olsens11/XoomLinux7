# Replacement MZ600 — physical, read-only alternate GPT proof and classic BigPart preflight

**Date:** Sunday 2026-10-25 EDT, evening. **Hardware:** Replacement experimental Motorola Xoom MZ600 Stingray CDMA ONLY. **Verdict:** OEM GPT and old-layout geometry physically verified, read-only ARM32 64-bit seek diagnostic **PASS**; BigPart **NOT INSTALLED**. No block writes, flash or formatting.

## Physical sequence (all read-only except normal reboot into recovery and RAM temporary)

1. Surface USB COM9 CDC ACM `PING` returned `PONG XOOM-LINUX V20`; `WIFI_STATUS` showed no wlan0 or Wi-Fi modules, `BT_STATUS` no hci0 or Bluetooth modules. This remains the known v06.3 Linux diagnostic baseline.
2. Used the existing **two-stage armed+confirmed USB REBOOT** under an independently validated MZ600 endpoint. Reboot ACK accepted; original Android Stingray (`ro.hardware=stingray`, `ro.product.device=stingray`, `sys.boot_completed=1`) returned via ADB. Its factory partition enumeration p1..p10 and by-name mapping read back correctly.
3. From Android issued **ADB reboot recovery** on the same verified device. **TWRP 3.1.1-0** reported `uid=0`, 62,521,344 eMMC 512-byte sectors, p8 system **524,288 sectors**, p9 cache **346,112**, p10 userdata **61,522,944**. Its /proc/cmdline contains `gpt gpt_sector=0x03b9dfff`, i.e. relocated GPT at LBA **62,513,151**. `dmesg` states `Primary GPT is invalid, using alternate GPT` and enumerates all ten partitions. This does not mean BigPart has already been applied.
4. A read-only 12MiB eMMC tail capture through TWRP's 2013 `/sbin/dd` (BusyBox 1.21.1-jb bionic, 32-bit) copied to Surface and SHA256-verified; unexpectedly **every byte 0xFF**. Exact private capture `private-backups/replacement-mz600-2026-10-25/MZ600-emmc-tail-12MiB-READONLY-20261025.img`, SHA256 `6747318cfda6f6bb9e77ee1c229d37b1799610bc1d41e5165cc40ccf2363a7c4`. DO NOT interpret this read as missing GPT—the old tool's large `skip` evidently did not read the intended LBA. Exact root cause within BusyBox not independently characterized.
5. Wrote and compiled a **tiny 2,180-byte freestanding ARMv7 ELF** that opens only `/dev/block/mmcblk0` with O_RDONLY, uses Linux `_llseek` to position at full 64-bit offsets, reads three 512B sectors, and emits only a short hex preview/signature and byte counts. Public source: [`scripts/experiments/mz600-readonly-gpt-sector-armv7.c`](../../scripts/experiments/mz600-readonly-gpt-sector-armv7.c). Build with pinned Arm GNU 14.3 gcc, `-Os -ffreestanding -fno-stack-protector -nostdlib -static -Wl,-e,_start -Wl,--build-id=none -s -lgcc`. Local ELF SHA256 `705db0543f03f375da4cdf2334121db457f09767c0a30086c9cc4a453cf0ac07`. It was hash-verified on Surface, pushed **only to TWRP /tmp RAM**, executed once on exact checked eMMC geometry, then unlinked. No filesystem/partition writes.
6. **PHYSICAL PASS** output: `OEM_BOOT_GPT_SECTOR LBA 62513151 first32=4546492050415254000000005c00000036d5014b00000000ffdfb90300000000 ff=2 zero=478 GPT_SIGNATURE_FOUND`; `EMMC_LAST_SECTOR LBA 62521343` was all FF; `FACTORY_SYSTEM_FIRST_SECTOR LBA 118784` was all zeros (first sector only). Exit code 0, `NO_BLOCK_DEVICE_WRITES_PERFORMED`.

## Engineering interpretation

There **is a valid-looking relocated GPT header at the actual OEM bootloader-specified LBA** on this MZ600; existing TWRP kernel actually accepted it and enumerated p1..p10. The bare `EFI PART` check is NOT independent proof of GPT header and entry-array CRC; the TWRP kernel's normal GPT validator supplies stronger indirect evidence. The original Schischu BigPart scheme maps the exact verified stock starts to 1GiB p8 system, 512MiB p9 cache, and remaining p10 without modifying GPT bytes, matching our prior [host-only layout auditor](MZ600_V064_ORIGINAL_BIGPART_LAYOUT_MATCH_OFFLINE_2026-10-25.md).

**Source adaptation needed:** Linux 7's `block/partitions/efi.c` presently has neither the traditional `gpt_sector` parsing nor original in-memory BigPart mapping. The 2013 Broadcom/Motorola mechanism can be brought forward with a strict MZ600/device/geometry opt-in and conventional valid GPT CRC checks; [prior Linux4.4 Xoom BigPart port](https://github.com/extremetempz/linux-kernel-xoom/tree/master/kernel/patches) demonstrates the architecture and a known `gpt` prefix-vs-`gpt_sector=` handler pitfall. **No formatting while current TWRP's p8 is still 256MiB.** A future read-only Linux7 temporary boot MUST list the expanded p8/p9/p10 extents accurately before any write.
