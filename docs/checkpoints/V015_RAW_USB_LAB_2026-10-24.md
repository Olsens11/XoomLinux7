- WIFI_STOP: both rc 0, clean unload.
- WIFI_DEBUG 3: device acknowledged, next WIFI_START reported debug 3; /sys/module/brcmfmac/parameters/debug read 3.
- WIFI_RETRY: clean brcmfmac/brcmutil unload then rc 0/rc 0 reload. WIFI_STOP afterward succeeded. No association, scanning or DHCP attempted.
- Following upload of OEM firmware, wlan0 remained absent; no evidence of F2 resolution.

## Why v015 succeeded
v014 read the default ttyGS0 N_TTY canonical/echo discipline, destroying integrity of arbitrary binary packets. v015 calls TCGETS/TCSETS with Linux termios flags to enable raw/non-echo operation, verifies the mode, fails closed if raw mode unavailable, handles partial file writes and aborts idle unfinished uploads. The 4KiB all-octet payload and 460KiB ARM module CRC results demonstrate the correction physically.

## Limitations and next experiment
Do not claim native Wi-Fi is working: BCM4329 firmware function 2 readiness timeout is not fixed, nor have MAC calibration and regulatory provenance been qualified. v015 is accepted as a *diagnostic infrastructure baseline*, not accepted wireless functionality. Review upstream Linux and OEM timings/SDIO F2 IOEx/IORx with live uploaded modules; avoid rewriting generic drivers or hard-coding identities.

Binary firmware, raw serial logs and unique device identifiers are private and not published. Running Xoom can revert by normal reboot; no persistence.
